SECTION 5: SUPABASE DATABASE SCHEMA
================================================================================

--- Table: profiles ---
create table profiles (
  id uuid references auth.users on delete cascade primary key,
  email text unique not null,
  role text default 'user' check (role in ('admin', 'user')),
  subscription_status text default 'inactive' check (subscription_status in ('active', 'inactive', 'expired', 'trial')),
  subscription_expires_at timestamptz,
  is_ad_free boolean default false,
  ads_watched_today int default 0,
  total_ads_watched int default 0,
  last_ad_watched_at timestamptz,
  selected_scenario_id uuid references scenarios(id),
  selected_scenario_name text,
  device_info jsonb,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

--- Table: scenarios ---
create table scenarios (
  id uuid default gen_random_uuid() primary key,
  admin_id uuid references profiles(id) not null,
  name text not null,
  description text,
  scenario_data jsonb not null,
  is_active boolean default true,
  is_global boolean default true,
  target_users uuid[] default null,
  version int default 1,
  created_at timestamptz default now(),
  updated_at timestamptz default now()
);

--- Table: user_scenarios ---
create table user_scenarios (
  id uuid default gen_random_uuid() primary key,
  user_id uuid references profiles(id) on delete cascade,
  scenario_id uuid references scenarios(id) on delete cascade,
  is_downloaded boolean default false,
  is_enabled boolean default true,
  downloaded_at timestamptz,
  unique(user_id, scenario_id)
);

--- Table: subscriptions ---
create table subscriptions (
  id uuid default gen_random_uuid() primary key,
  user_id uuid references profiles(id) on delete cascade,
  granted_by uuid references profiles(id),
  plan_type text default 'reward_ad' check (plan_type in ('reward_ad', 'admin_granted')),
  duration_days int,
  started_at timestamptz default now(),
  expires_at timestamptz,
  is_active boolean default true,
  note text,
  created_at timestamptz default now()
);

--- Table: ad_events ---
create table ad_events (
  id uuid default gen_random_uuid() primary key,
  user_id uuid references profiles(id),
  ad_type text not null,
  event_type text not null,
  revenue_estimate decimal(10,6),
  created_at timestamptz default now()
);

--- Table: click_sessions ---
create table click_sessions (
  id uuid default gen_random_uuid() primary key,
  user_id uuid references profiles(id),
  scenario_id uuid references scenarios(id),
  started_at timestamptz default now(),
  ended_at timestamptz,
  total_clicks int default 0,
  duration_seconds int,
  device_info jsonb
);

--- Table: app_settings ---
create table app_settings (
  id int primary key default 1,
  interstitial_interval_minutes int default 2,
  reward_ads_for_one_day int default 20,
  trial_days int default 3,
  updated_at timestamptz default now()
);

--- Table: admin_logs ---
create table admin_logs (
  id uuid default gen_random_uuid() primary key,
  admin_id uuid references profiles(id),
  action text not null,
  target_user_id uuid references profiles(id),
  details jsonb,
  created_at timestamptz default now()
);

--- Row Level Security (RLS) ---
- profiles: Users read own only. Admin reads all.
- scenarios: Admin full CRUD. Users read assigned only.
- user_scenarios: Users read own only. Admin reads all.
- subscriptions: Users read own only. Admin full access.
- ad_events: Users insert own. Admin reads all.
- click_sessions: Users insert own. Admin reads all.
- app_settings: Admin full CRUD. Users read-only.
- admin_logs: Admin read-only. Auto-inserted via Edge Functions.

--- Realtime Subscriptions ---
Enable Realtime on: scenarios, user_scenarios, profiles, app_settings
When admin updates scenario → all users receive update within 3 seconds.

SECTION 6: SCENARIO SELECTOR — "MODE" SYSTEM (SCENARIO NAME = SELECTOR)
================================================================================

CONCEPT:
Admin uploads up to 15 scenarios. Each scenario's NAME becomes a "Mode" option.
User sees a dropdown on first login listing all scenario names.
User selects one → that scenario downloads and applies.
The selected scenario name is saved to the user's profile.

USER FLOW — FIRST LOGIN:
1. User logs in successfully
2. App fetches list of all active scenarios from Supabase
3. Shows "Select Your Mode" screen with dropdown
4. User picks a scenario name (e.g., "English", "Hindi", "Game Mode", "Farm Mode")
5. Save selected_scenario_id and selected_scenario_name to profiles
6. Download scenario JSON, store in Room DB
7. Redirect to Home Screen

USER FLOW — CHANGE MODE:
1. User taps "Mode: [Name] ▼" on home screen header
2. Dropdown shows all available scenario names
3. User selects different scenario
4. Download new scenario JSON
5. Replace active scenario
6. Show toast: "✅ Switched to [Scenario Name]"
7. If download fails → Keep previous, show error

ADMIN FLOW — CREATE SCENARIO:
1. Admin opens "Create Scenario"
2. Enters Scenario Name (this becomes the mode option users see)
3. Builds scenario using visual editor
4. Publishes → appears in all users' dropdown instantly

MAXIMUM: 15 scenarios total. Enforce in admin UI.

EDGE CASES:
- No scenarios published → "No modes available. Check back later."
- Selected scenario deleted → Auto-switch to first available, notify user
- Scenario updated by admin → Auto-download latest, notify user
- User offline → Show cached list, use last selected

SECTION 8: AUTO CLICKER CORE FUNCTIONALITY
================================================================================

ACCESSIBILITY SERVICE:
- Fork from Smart-AutoClicker GitHub repo
- Service name: AutopilotService
- Permission: BIND_ACCESSIBILITY_SERVICE
- Overlay window for floating Start/Stop mini buttons
- Foreground notification when running

SCENARIO EXECUTION ENGINE:
- Parse scenario JSON from Supabase
- Supported actions:
  • CLICK — x, y, duration
  • SWIPE — startX, startY, endX, endY, duration
  • DELAY — milliseconds
  • CONDITION — image match, color match, text match (OCR)
  • LOOP — repeat count or infinite
- Execute via AccessibilityNodeInfo.performAction()
- Anti-detection: Randomized timing (±50ms jitter), human-like swipe paths
- Stop: User presses Stop, scenario completes, or error occurs

SCENARIO JSON FORMAT:
{
  "version": 1,
  "name": "English",
  "actions": [
    {"type": "click", "x": 540, "y": 1200, "delay_after": 500},
    {"type": "swipe", "startX": 540, "startY": 1500, "endX": 540, "endY": 800, "duration": 300},
    {"type": "condition", "condition_type": "image_match", "image_hash": "abc123", "timeout": 5000, "if_true": [...], "if_false": [...]},
    {"type": "loop", "count": 10, "actions": [...]}
  ]
}

SECTION 10: SUBSCRIPTION SYSTEM (100% FREE — NO PAYMENTS)
================================================================================

SUBSCRIPTION STATES:
- trial — New user gets 3-day free trial
- active — Earned via reward ads or admin grant
- expired — Ended, must watch ads or wait for admin
- inactive — Never subscribed

ON APP LAUNCH:
1. Check subscription_expires_at in profiles
2. If expired and not trial → "Watch 20 Ads to Unlock" full-screen modal
3. If trial active → "X days left in trial" banner
4. If active → Full access

ON REWARD AD COMPLETION (20th ad):
1. Check active subscription
2. If active → Extend expires_at by 1 day
3. If expired/inactive → Set expires_at = NOW() + 1 day
4. Set subscription_status = 'active'
5. Reset ads_watched_today = 0
6. Insert into subscriptions (plan_type='reward_ad', duration_days=1)
7. Show success animation + notification

ADMIN GRANTS SUBSCRIPTION:
1. Admin selects user → chooses duration
2. If lifetime → expires_at = '2099-12-31', duration_days = 99999
3. Else → expires_at = NOW() + duration_days
4. Set subscription_status = 'active'
5. Insert into subscriptions (plan_type='admin_granted')
6. Log in admin_logs
7. Send push notification to user
8. If lifetime → Fireworks animation on user's device

ADMIN MAKES USER AD-FREE:
1. Set profiles.is_ad_free = true
2. Log in admin_logs
3. Send push: "✨ You are now ad-free!"
4. Immediately hide all ad UI

ADMIN REMOVES AD-FREE:
1. Set profiles.is_ad_free = false
2. Log in admin_logs
3. Send push: "Your ad-free status has been removed."
4. Immediately restore all ad UI

DAILY CRON JOB (Supabase Edge Function):
1. Reset ads_watched_today = 0 for all users at 00:00 UTC
2. Check expired subscriptions, update to 'expired'
3. Send push: "Your subscription expired! Watch 20 ads to renew FREE"
